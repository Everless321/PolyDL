# 修复长视频下载不完整问题（dYm Issue #9）

## 背景
dYm Issue #9：长视频（10min+）下载完成后能播放，但时长远短于实际。

根因定位在 dyDownloader（本仓库）`src/downloader/douyin.ts` 的 `downloadFile`：
- `got.stream` + `pipeline` 不校验 Content-Length 与实际写入字节
- 服务端/CDN 在长连接中途断开（FIN 后数据未传完），对 Node stream 是一次"正常 end"，`pipeline` 直接 resolve
- got 的 retry 只对抛错生效，截断场景永不重试
- 下游 dYmanager 的 `download-validator.ts` 只查"非 0KB + 扩展名"，截断 mp4 一路放行

## 待办
- [x] HEAD 预检拿 Content-Length（失败则降级到响应头）
- [x] response 事件兜底再取一次 content-length
- [x] pipeline 完成后比对字节数，截断则抛错
- [x] 抛错让 dYmanager 上层重试链路接管
- [x] 兼容 chunked 编码（无 Content-Length 时退回原行为）

## 最终执行
修改 `src/downloader/douyin.ts:downloadFile`：
1. 下载前 `got.head(url)` 拿 `content-length`，失败/不支持时静默降级
2. `downloadStream.on('response')` 再取一次 header 作为兜底
3. `pipeline` 完成后：若有 expectedSize 则严格比对 `tmpStat.size === expectedSize`，不匹配抛 `Error('Incomplete download: expected X bytes, got Y bytes')`
4. 外层 catch 已会清理 tmp 并返回 `{ success: false, error }`，dYmanager 端 `createDownloadTasks` 的重试逻辑接管

未触及范围：
- 不动 M3U8 直播流下载（chunked，本就无 Content-Length）
- 不动静态文件保存（saveStaticFile，内容来自内存非网络流）
- 不动 dYmanager（上游修好后下游校验自动生效）
